**¿Por qué LangChain?**
Por supuesto, puedes construir aplicaciones con LLM sin utilizar LangChain. La alternativa más obvia es usar el kit de desarrollo de software (SDK), es decir, el paquete que expone los métodos de su API HTTP como funciones en el lenguaje de programación de tu elección, del proveedor de LLM que hayas probado primero (por ejemplo, OpenAI). Consideramos que aprender LangChain tendrá beneficios tanto a corto como a largo plazo por los siguientes factores:

***Patrones comunes preconstruidos***  
LangChain incluye implementaciones de referencia para los patrones más comunes de aplicaciones con LLM (mencionamos algunos en el prefacio: cadena de pensamiento, llamada a herramientas y otros). Esta es la forma más rápida de comenzar con LLM y, a menudo, puede ser todo lo que necesites. Sugerimos iniciar cualquier nueva aplicación a partir de estos patrones y comprobar si los resultados predeterminados son suficientes para tu caso de uso. Si no lo son, entonces entra en juego el siguiente punto, que representa la otra mitad de las bibliotecas de LangChain.

***Componentes intercambiables***  
Estos son componentes que pueden sustituirse fácilmente por alternativas. Cada componente (un LLM, modelo de chat, analizador de salida, etc.) sigue una especificación compartida, lo que hace que tu aplicación sea más resistente al futuro. A medida que los proveedores de modelos lancen nuevas capacidades y cambien tus necesidades, podrás evolucionar tu aplicación sin necesidad de reescribirla completamente cada vez.

A lo largo de este libro utilizamos los siguientes componentes principales en los ejemplos de código:
- LLM/modelo de chat: OpenAI
- Embeddings: OpenAI
- Vector store: PGVector

Puedes reemplazar cada uno de estos por cualquiera de las alternativas disponibles:

***Modelos de chat***  
Consulta la documentación de LangChain. Si no deseas usar OpenAI (una API comercial), sugerimos Anthropic como alternativa comercial u Ollama como opción de código abierto.

***Embeddings***  
Consulta la documentación de LangChain. Si no deseas usar OpenAI, sugerimos Cohere como alternativa comercial u Ollama como opción de código abierto.

***Vector stores***  
Consulta la documentación de LangChain. Si no deseas usar PGVector (una extensión de código abierto para la popular base de datos SQL Postgres), sugerimos Weaviate (una base de datos vectorial dedicada) o OpenSearch (funciones de búsqueda vectorial integradas en una base de datos de búsqueda popular).

Este esfuerzo va más allá de simplemente hacer que todos los LLM tengan los mismos métodos, con argumentos y valores de retorno similares. Veamos el ejemplo de modelos de chat y dos proveedores populares de LLM: OpenAI y Anthropic. Ambos tienen una API de chat que recibe mensajes (objetos con un tipo y contenido) y devuelve un nuevo mensaje generado por el modelo. Sin embargo, si intentas usar ambos modelos en la misma conversación, rápidamente surgirán problemas, ya que sus formatos de mensajes son sutilmente incompatibles. LangChain abstrae estas diferencias para permitir construir aplicaciones verdaderamente independientes de un proveedor específico. Por ejemplo, con LangChain, una conversación de chatbot que utiliza tanto modelos de OpenAI como de Anthropic puede funcionar.

Finalmente, a medida que desarrollas aplicaciones más complejas con varios de estos componentes, hemos encontrado especialmente útil la capacidad de orquestación de LangChain:
- Todos los componentes principales están instrumentados mediante un sistema de callbacks para observabilidad (más sobre esto en el Capítulo 8).

- Las aplicaciones con LLM de larga duración pueden interrumpirse, reanudarse o reintentarse (más sobre esto en el Capítulo 6).

# Using LLMs in LangChain
Para recapitular, los LLM son el motor principal detrás de la mayoría de las aplicaciones de IA generativa. LangChain proporciona dos interfaces simples para interactuar con cualquier proveedor de API de LLM:

- Chat Models (Modelos de chat)
- LLMs

La interfaz LLM simplemente toma un prompt de texto como entrada, envía esa entrada al proveedor del modelo y luego devuelve la predicción del modelo como salida.

Importemos el wrapper de ~~OpenAI~~ groq para LLM de LangChain para invocar una predicción del modelo utilizando un prompt simple:
```python
from langchain_groq import ChatGroq
from dotenv import load_dotenv
import os

load_dotenv()
groq_api_key = os.getenv('GROQ_API_KEY')

model = ChatGroq(model="qwen/qwen3-32b", api_key=groq_api_key)
model.invoke("The sky is...")
```

---

***Tip***
Observa el parámetro `model` que se pasa a groq. Este es el parámetro más común de configurar al utilizar un LLM o modelo de chat: el modelo subyacente que se usará, ya que la mayoría de los proveedores ofrecen varios modelos con diferentes compensaciones entre capacidad y costo (generalmente, los modelos más grandes son más capaces, pero también más costosos y lentos). Consulta la descripción general de los modelos que ofrece OpenAI.

Otros parámetros útiles para configurar, disponibles en la mayoría de los proveedores, incluyen los siguientes:

`temperature`  
Esto controla el algoritmo de muestreo utilizado para generar la salida. Valores más bajos producen resultados más predecibles (por ejemplo, 0.1), mientras que valores más altos generan respuestas más creativas o inesperadas (como 0.9). Diferentes tareas requieren distintos valores para este parámetro. Por ejemplo, producir salidas estructuradas suele beneficiarse de una temperatura baja, mientras que tareas de escritura creativa funcionan mejor con valores más altos.

`max_tokens`  
Esto limita el tamaño (y el costo) de la salida. Un valor demasiado bajo puede hacer que el LLM deje de generar antes de alcanzar un final natural, por lo que la respuesta puede parecer truncada.

Más allá de estos, cada proveedor expone un conjunto diferente de parámetros. Recomendamos consultar la documentación del proveedor que elijas. Como ejemplo, puedes revisar la plataforma de groq.

---

Alternativamente, la interfaz de modelo de chat permite conversaciones de ida y vuelta entre el usuario y el modelo. La razón por la que es una interfaz separada es que proveedores populares de LLM como OpenAI diferencian los mensajes enviados hacia y desde el modelo en roles de usuario, asistente y sistema (aquí, rol denota el tipo de contenido que contiene el mensaje):

***System Role***  
Se utiliza para instrucciones que el modelo debe seguir al responder una pregunta del usuario.

***User Role***  
Se utiliza para la consulta del usuario y cualquier otro contenido producido por este.

***Assistant Role***  
Se utiliza para el contenido generado por el modelo.

La interfaz del modelo de chat facilita la configuración y gestión de conversaciones en tu aplicación de chatbot con IA. Aquí tienes un ejemplo utilizando el modelo groq de LangChain:
```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage

model = ChatGroq(model="openai/gpt-oss-120b")
prompt = [HumanMessage("What is the capital of France?")]

model.invoke(prompt)
```

Output:

En lugar de una única cadena de prompt, los modelos de chat utilizan diferentes tipos de interfaces de mensajes asociados con cada uno de los roles mencionados anteriormente. Estos incluyen los siguientes:

`HumanMessage`  
Un mensaje enviado desde la perspectiva del humano, con el rol de usuario.

`AIMessage`  
Un mensaje enviado desde la perspectiva de la IA con la que interactúa el humano, con el rol de asistente.

`SystemMessage`  
Un mensaje que establece las instrucciones que la IA debe seguir, con el rol de sistema.

`ChatMessage`  
Un mensaje que permite establecer arbitrariamente cualquier rol.

Incorporemos una instrucción `SystemMessage` en nuestro ejemplo:
```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage

model = ChatGroq(model="openai/gpt-oss-120b")
messages = [ 
    ("system", """You are a helpful assistant that responds to questions with three exclamation marks."""),
    ("human", "What is the capital of France?")
]

model.invoke(messages)
```

Output:
```python
Paris
```

Como puedes ver, el modelo obedeció la instrucción proporcionada en el `SystemMessage` aunque no estuviera presente en la pregunta del usuario. Esto te permite preconfigurar tu aplicación de IA para que responda de una manera relativamente predecible según la entrada del usuario.
