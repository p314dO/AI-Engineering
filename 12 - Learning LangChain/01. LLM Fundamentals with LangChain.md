# Using LLMs in LangChain
Para recapitular, los LLM son el motor principal detrás de la mayoría de las aplicaciones de IA generativa. LangChain proporciona dos interfaces simples para interactuar con cualquier proveedor de API de LLM:

- Chat Models (Modelos de chat)
- LLMs

La interfaz LLM simplemente toma un prompt de texto como entrada, envía esa entrada al proveedor del modelo y luego devuelve la predicción del modelo como salida.

Importemos el wrapper de ~~OpenAI~~ groq para LLM de LangChain para invocar una predicción del modelo utilizando un prompt simple:
```python
from langchain_groq import ChatGroq
from dotenv import load_dotenv
import os

load_dotenv()
groq_api_key = os.getenv('GROQ_API_KEY')

model = ChatGroq(model="qwen/qwen3-32b", api_key=groq_api_key)
model.invoke("The sky is...")
```

---

***Tip***
Observa el parámetro `model` que se pasa a groq. Este es el parámetro más común de configurar al utilizar un LLM o modelo de chat: el modelo subyacente que se usará, ya que la mayoría de los proveedores ofrecen varios modelos con diferentes compensaciones entre capacidad y costo (generalmente, los modelos más grandes son más capaces, pero también más costosos y lentos). Consulta la descripción general de los modelos que ofrece OpenAI.

Otros parámetros útiles para configurar, disponibles en la mayoría de los proveedores, incluyen los siguientes:

`temperature`  
Esto controla el algoritmo de muestreo utilizado para generar la salida. Valores más bajos producen resultados más predecibles (por ejemplo, 0.1), mientras que valores más altos generan respuestas más creativas o inesperadas (como 0.9). Diferentes tareas requieren distintos valores para este parámetro. Por ejemplo, producir salidas estructuradas suele beneficiarse de una temperatura baja, mientras que tareas de escritura creativa funcionan mejor con valores más altos.

`max_tokens`  
Esto limita el tamaño (y el costo) de la salida. Un valor demasiado bajo puede hacer que el LLM deje de generar antes de alcanzar un final natural, por lo que la respuesta puede parecer truncada.

Más allá de estos, cada proveedor expone un conjunto diferente de parámetros. Recomendamos consultar la documentación del proveedor que elijas. Como ejemplo, puedes revisar la plataforma de groq.

---

Alternativamente, la interfaz de modelo de chat permite conversaciones de ida y vuelta entre el usuario y el modelo. La razón por la que es una interfaz separada es que proveedores populares de LLM como OpenAI diferencian los mensajes enviados hacia y desde el modelo en roles de usuario, asistente y sistema (aquí, rol denota el tipo de contenido que contiene el mensaje):

***System Role***  
Se utiliza para instrucciones que el modelo debe seguir al responder una pregunta del usuario.

***User Role***  
Se utiliza para la consulta del usuario y cualquier otro contenido producido por este.

***Assistant Role***  
Se utiliza para el contenido generado por el modelo.

La interfaz del modelo de chat facilita la configuración y gestión de conversaciones en tu aplicación de chatbot con IA. Aquí tienes un ejemplo utilizando el modelo groq de LangChain:
```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage

model = ChatGroq(model="openai/gpt-oss-120b")
prompt = [HumanMessage("What is the capital of France?")]

model.invoke(prompt)
```

Output:

En lugar de una única cadena de prompt, los modelos de chat utilizan diferentes tipos de interfaces de mensajes asociados con cada uno de los roles mencionados anteriormente. Estos incluyen los siguientes:

`HumanMessage`  
Un mensaje enviado desde la perspectiva del humano, con el rol de usuario.

`AIMessage`  
Un mensaje enviado desde la perspectiva de la IA con la que interactúa el humano, con el rol de asistente.

`SystemMessage`  
Un mensaje que establece las instrucciones que la IA debe seguir, con el rol de sistema.

`ChatMessage`  
Un mensaje que permite establecer arbitrariamente cualquier rol.

```python
messages = [ 
    ("system", """You are a helpful assistant that responds to questions with three exclamation marks."""),
    ("human", "What is the capital of France?")
]

model.invoke(messages)
```

# Making LLM Prompts Reusable
La sección anterior mostró cómo la instrucción del prompt influye significativamente en la salida del modelo. Los prompts ayudan al modelo a comprender el contexto y generar respuestas relevantes a las consultas.

Aquí tienes un ejemplo de un prompt detallado:
```python
Answer the question based on the context below. If the question cannot be
answered using the information provided, answer with "I don't know".

Context: The most recent advancements in NLP are being driven by Large Language 
Models (LLMs). These models outperform their smaller counterparts and have
become invaluable for developers who are creating applications with NLP 
capabilities. Developers can tap into these models through Hugging Face's
`transformers` library, or by utilizing OpenAI and Cohere's offerings through
the `openai` and `cohere` libraries, respectively.

Question: Which model providers offer LLMs?

Answer:
```

Aunque el prompt parece una cadena de texto simple, el desafío está en determinar qué contenido debe incluir y cómo debe variar según la entrada del usuario. En este ejemplo, los valores de Contexto y Pregunta están codificados de forma fija, pero ¿qué sucede si queremos pasarlos dinámicamente?

Afortunadamente, LangChain proporciona interfaces de plantillas de prompts que facilitan la construcción de prompts con entradas dinámicas:
```python
from langchain_core.prompts import PromptTemplate

template = PromptTemplate.from_template(
    """Answer the question based on the
    context below. If the question cannot be answered using the information 
    provided, answer with "I don't know".

Context: {context}

Question: {question}

Answer: """
)

template.invoke({
    "context": """The most recent advancements in NLP are being driven by Large 
        Language Models (LLMs). These models outperform their smaller 
        counterparts and have become invaluable for developers who are creating 
        applications with NLP capabilities. Developers can tap into these 
        models through Hugging Face's `transformers` library, or by utilizing 
        OpenAI and Cohere's offerings through the `openai` and `cohere` 
        libraries, respectively.""",
    "question": "Which model providers offer LLMs?"
})
```

Output:

# Getting Specific Formats out of LLMs
Las salidas en texto plano son útiles, pero puede haber casos de uso en los que necesites que el LLM genere una salida estructurada; es decir, un formato legible por máquinas como JSON, XML, CSV o incluso lenguajes de programación como Python o JavaScript. Esto resulta muy útil cuando planeas pasar esa salida a otra parte de tu código, haciendo que el LLM forme parte de una aplicación más grande.

## JSON Output
El formato más común para generar con LLM es JSON. Las salidas JSON pueden, por ejemplo, enviarse a tu frontend o almacenarse en una base de datos.

Al generar JSON, la primera tarea es definir el esquema que deseas que el LLM respete al producir la salida. Luego, debes incluir ese esquema en el prompt, junto con el texto fuente que deseas utilizar. Veamos un ejemplo:
```python
from langchain_groq import ChatGroq
# from langchain_core.pydantic_v1 import BaseModel
from pydantic import BaseModel

class AnswerWithJustification(BaseModel):
    '''An answer to the user's question along with justification for the 
        answer.'''
    answer: str
    '''The answer to the user's question'''
    justification: str
    '''Justification for the answer'''

llm = ChatGroq(model="openai/gpt-oss-120b", temperature=0)
structured_llm = llm.with_structured_output(AnswerWithJustification)

structured_llm.invoke("""What weighs more, a pound of bricks or a pound of feathers""")
```

Output:
```python
answer='They weigh the same—both are one pound.', 
justification='A pound is a unit of weight. Whether the material is bricks or feathers, a pound of any substance has the same weight. The difference lies only in volume and density: a pound of feathers occupies much more space than a pound of bricks, but the weight is identical.'
```

Entonces, primero define un esquema. En Python, la forma más sencilla de hacerlo es con Pydantic (una biblioteca utilizada para validar datos contra esquemas). En JavaScript, esto suele hacerse con Zod (una biblioteca equivalente). El método `with_structured_output` utilizará ese esquema para dos propósitos:

- El esquema se convertirá en un objeto JSONSchema (un formato JSON utilizado para describir la estructura —tipos, nombres, descripciones— de datos JSON), que será enviado al LLM. Para cada LLM, LangChain selecciona el mejor método para hacerlo, generalmente mediante llamada a funciones o prompting.
- El esquema también se utilizará para validar la salida devuelta por el LLM antes de retornarla; esto garantiza que la salida producida respete exactamente el esquema que proporcionaste.

## Other Machine-Readable Formats with Output Parsers
También puedes utilizar un LLM o modelo de chat para producir salidas en otros formatos, como CSV o XML. Aquí es donde los analizadores de salida (output parsers) resultan especialmente útiles. Los output parsers son clases que ayudan a estructurar las respuestas generadas por modelos de lenguaje. Cumplen dos funciones principales:

***Providing format instructions***
Los output parsers pueden utilizarse para inyectar instrucciones adicionales en el prompt que ayuden a guiar al LLM para que produzca texto en un formato que el parser pueda interpretar correctamente.

***Validating and parsing output***
Su función principal es tomar la salida textual del LLM o modelo de chat y transformarla en un formato más estructurado, como una lista, XML u otros formatos. Esto puede incluir eliminar información innecesaria, corregir salidas incompletas y validar los valores obtenidos.

Aquí tienes un ejemplo de cómo funciona un output parser:
```python
from langchain_core.output_parsers import CommaSeparatedListOutputParser
parser = CommaSeparatedListOutputParser()
items = parser.invoke("apple, banana, cherry")
items
```

Output
```python
['apple', 'banana', 'cherry']
```

# Assembling the Many Pieces of an LLM Application
Como habrás notado, todos los ejemplos de código utilizados hasta ahora emplean una interfaz similar y el método `invoke()` para generar salidas desde el modelo (o plantilla de prompt, o analizador de salida). Todos los componentes tienen lo siguiente:

- Existe una interfaz común con estos métodos:
	- `invoke`: transforma una única entrada en una salida.
	- `batch`: transforma eficientemente múltiples entradas en múltiples salidas.
	- `stream`: transmite la salida de una única entrada a medida que se produce.
- También existen utilidades integradas para reintentos, alternativas de respaldo, esquemas y configurabilidad en tiempo de ejecución.
- En Python, cada uno de estos tres métodos tiene equivalentes basados en `asyncio`.

De esta manera, todos los componentes se comportan de forma consistente, y la interfaz que aprendes para uno de ellos se aplica a todos:

```python
from langchain_groq import ChatGroq

model = ChatGroq(model="openai/gpt-oss-120b")

completion = model.invoke('Hi There!')
completion

completions = model.batch(['Hi there!', 'Bye!'])
completions

for token in model.stream("Bye!"):
    print(token)
```

En este ejemplo, puedes ver cómo funcionan los tres métodos principales:
- `invoke()` toma una única entrada y devuelve una única salida.
- `batch()` toma una lista de entradas y devuelve una lista de salidas.
- `stream()` toma una única entrada y devuelve un iterador con partes de la salida a medida que están disponibles.

En algunos casos, cuando el componente subyacente no admite salida iterativa, habrá una sola parte que contendrá toda la salida.

Puedes combinar estos componentes de dos maneras:

***Imperativa***  
Llamando directamente a tus componentes, por ejemplo, con `model.invoke(...)`

***Declarativa***  
Utilizando el Lenguaje de Expresiones de LangChain (LCEL), como se cubrirá en una próxima sección.

La Tabla 1-1 resume sus diferencias, y veremos cada una en acción a continuación.

Tabla 1-1. Principales diferencias entre composición imperativa y declarativa.

| Característica [[1](https://blog.ndepend.com/declarative-programming-depth/)] | Imperativa                                                                | Declarativa |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ----------- |
| **Sintaxis**                                                                  | Todo Python o JavaScript                                                  | LCEL        |
| **Ejecución en paralelo**                                                     | **Python:** con hilos o corrutinas  <br>**JavaScript:** con `Promise.all` | Automática  |

## Imperative Composition
La composición imperativa es simplemente una forma elegante de referirse a escribir el código como estás acostumbrado, componiendo estos componentes en funciones y clases. Aquí tienes un ejemplo que combina prompts, modelos y analizadores de salida:

```python
from langchain_groq import ChatGroq
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import chain

# the building blocks
template = ChatPromptTemplate.from_messages([
    ('system', 'You are a helpful assistant.'),
    ('human', '{question}')
])

model = ChatGroq(model="openai/gpt-oss-120b")

# Combine them in a function
# @chain decorator adds the same Runnable interface for any function you write

@chain
def chatbot(values):
    prompt = template.invoke(values)
    return model.invoke(prompt)

# Use it
chatbot.invoke({"question": "Which model providers offer LLMs?"})
```

Output
```python
AIMessage(content='Below is a non‑exhaustive list of the most well‑known **LLM (large‑language‑model) providers** as of\u202f2024, grouped by the type of offering they focus on (cloud‑hosted APIs, managed services, or open‑source releases).\u202fFeel free to use this as a quick reference when you’re deciding ...snip...
```

Lo anterior es un ejemplo completo de un chatbot, utilizando un prompt y un modelo de chat. Como puedes ver, usa una sintaxis familiar de Python y admite cualquier lógica personalizada que desees agregar en esa función.

Por otro lado, si deseas habilitar soporte para streaming o ejecución asíncrona, tendrás que modificar tu función para admitirlo. Por ejemplo, el soporte de streaming puede añadirse de la siguiente manera:
```python
@chain
def chatbot(values):
    prompt = template.invoke(values)
    
    for token in model.stream(prompt):
        yield token # yield turns a standard function into a generator
                    # return: Ends the function completely and destroys its local variables.
                    # yield: Pauses the function, saves its state, and yields a single value [1]. The function resumes right after the yield statement when called again

for part in chatbot.stream({
    "question":"Which model providers offer LLMs?"
}):
    print(part)
```

Output
```python
AIMessageChunk(content="Hugging")
AIMessageChunk(content=" Face's")
AIMessageChunk(content=" `transformers`")
```

Entonces, tanto en JavaScript como en Python, puedes habilitar streaming para tu función personalizada utilizando `yield` para emitir los valores que deseas transmitir y luego llamándola con `stream`.

Para la ejecución asíncrona, reescribirías tu función de la siguiente manera:
```python
@chain
async def chatbot(values):
    prompt = await template.ainvoke(values)
    return await model.ainvoke(prompt)

await chatbot.ainvoke({"question":"Which model providers offer LLMs?"})
```

Esto aplica solo a Python, ya que la ejecución asíncrona es la única opción en JavaScript.

## Declarative Composition
LCEL es un lenguaje declarativo para componer componentes de LangChain. LangChain compila las composiciones en LCEL en un plan de ejecución optimizado, con paralelización automática, streaming, trazabilidad y soporte asíncrono.

Veamos el mismo ejemplo utilizando LCEL:
```python
from langchain_groq import ChatGroq
from langchain_core.prompts import ChatPromptTemplate

#the building blocks

template = ChatPromptTemplate.from_messages([
    ('system', 'You are a helpful assistant.'),
    ('human', '{question}'),
])

model = ChatGroq(model="openai/gpt-oss-120b")

# Combine them with the | operator
chatbot = template | model

# Use it
chatbot.invoke({"question": "Which model providers offer LLMs?"})
```

Es fundamental notar que la última línea es la misma en ambos ejemplos; es decir, utilizas tanto la función como la secuencia LCEL de la misma manera, con `invoke`/`stream`/`batch`. Y en esta versión, no necesitas hacer nada adicional para utilizar streaming:
```python
chatbot = template | model

for part in chatbot.stream({
    "question":"Which model providers offer LLMs?"
}):
    print(part)
```

Y, solo para Python, ocurre lo mismo al utilizar métodos asíncronos:
```python
chatbot = template | model

await chatbot.ainvoke({
    "question": "Which model providers offer LLMs?"
})
```

# Summary
En este capítulo, aprendiste sobre los componentes fundamentales y bloques de construcción necesarios para crear aplicaciones con LLM utilizando LangChain. Las aplicaciones basadas en LLM son esencialmente una cadena compuesta por el modelo de lenguaje para realizar predicciones, las instrucciones del prompt para guiar al modelo hacia una salida deseada y, opcionalmente, un analizador de salida para transformar el formato de la respuesta generada.

Todos los componentes de LangChain comparten la misma interfaz con los métodos `invoke`, `stream` y `batch` para manejar diversas entradas y salidas. Estos componentes pueden combinarse y ejecutarse de dos maneras: de forma imperativa, llamándolos directamente, o de forma declarativa, utilizando LCEL.

El enfoque imperativo es útil si planeas escribir mucha lógica personalizada, mientras que el enfoque declarativo resulta útil para ensamblar componentes existentes con una personalización limitada.
